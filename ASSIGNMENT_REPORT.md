## 1. Introduction

The project is a backend application that manages student records through a REST API. It is developed using Python and FastAPI, with SQLite for persistent storage.

## 2. Objectives

- Implement Create, Read, Update, and Delete operations.
- Store student information persistently in SQLite.
- Provide API endpoints to list, filter, retrieve, update, and delete records.
- Validate inputs and handle duplicate email and missing records.
- Document the API and provide repeatable installation and testing instructions.
- Explore a local AI extension as an optional enhancement.

## 3. Technology stack

- **Python:** application programming language.
- **FastAPI:** REST API framework and interactive documentation.
- **SQLite:** local relational database.
- **SQLAlchemy:** Python ORM for database models and queries.
- **Pydantic:** request and response validation.
- **Uvicorn:** development ASGI server.
- **Pytest / HTTPX:** API testing.
- **Ollama (optional):** local language model for natural-language questions.

## 4. Student data model

| Field | Purpose |
|---|---|
| `student_id` | Unique primary key generated by the database |
| `name` | Student name |
| `date_of_birth` | Date of birth in `YYYY-MM-DD` format |
| `email` | Contact email; must be unique |
| `phone` | Optional phone number |
| `course` | Optional course name |
| `address` | Optional address |
| `enrollment_date` | Optional enrollment date |

## 5. API design

| Method | Endpoint | Description |
|---|---|---|
| GET | `/` | Check API status |
| POST | `/students` | Add a student |
| GET | `/students` | List/filter students |
| GET | `/students/{student_id}` | Fetch one student |
| PUT | `/students/{student_id}` | Update student details |
| PATCH | `/students/{student_id}` | Update selected fields |
| DELETE | `/students/{student_id}` | Delete a student |
| POST | `/ai/ask` | Optional AI question endpoint |

## 6. Architecture and workflow

1. A client sends an HTTP request to a FastAPI endpoint.
2. Pydantic validates the request body and field types.
3. The route calls a function in `crud.py`.
4. SQLAlchemy reads or changes the SQLite database.
5. The API returns the result as JSON with an appropriate HTTP status code.

## 7. Validation and error handling

- Invalid request fields are rejected by request validation.
- Duplicate email is handled as a conflict response.
- A missing student returns HTTP `404`.
- Deletion returns HTTP `204` when successful.
- The database uses a primary key for unique student identification.

## 8. How to run

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Open `http://127.0.0.1:8000/docs` and test the endpoints. On Windows, activate the environment using `.venv\\Scripts\\Activate.ps1`.

## 9. Testing plan

- Update one or more fields and verify the changes.
- Delete the student and confirm a later GET returns `404`.
- Try duplicate email and invalid data to observe error handling.

Test results should be recorded after running the project in the user's own environment; this report does not claim a live test run.

## 10. Optional AI extension

Ollama may be used to answer questions about records. Backend code selects relevant records and supplies them as context. The model must not generate or execute unrestricted SQL. This component is optional; the FastAPI + SQLite CRUD application is the required core.

## 11. Security and limitations

Use fictional/demo data. Do not publish real student information, passwords, API secrets, the local database file, or virtual environment. Ollama must be installed and running separately to use the optional AI endpoint. The project is intended as an internship learning project and would need further authentication, authorization, deployment configuration, and operational hardening before production use.

## 12. Conclusion

The application demonstrates the design of a Python REST API, relational data persistence, CRUD operations, validation, HTTP error handling, and API testing.
